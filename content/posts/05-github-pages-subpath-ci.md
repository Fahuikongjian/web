首页能打开，封面却一张也看不见，是子路径部署里很有辨识度的故障。浏览器收到了页面，却去域名根目录找资源。星环手记在根路径预览时看不出这个问题，于是我把项目站点的挂载前缀也放进构建校验。前缀在发布前就进入实际产物，点开一条坏链接时，也能直接检查对应的输出文件。

## 源稿只记站内路由

Markdown 里的[文章归档](/articles/)保留根相对写法。构建时由 `--base-path` 提供挂载前缀，再统一改写输出页面里的站内 `href` 和 `src`，代码块里的示例保留原样。搜索索引也要拿到同一个前缀，否则站内导航走得通，搜索结果却可能跳回域名根目录。

```bash
# SITE_URL 使用完整站点地址，包含项目站点的挂载前缀
python scripts/check.py \
  --base-path /starloop \
  --site-url "${SITE_URL:?Set SITE_URL first}"
```

`--site-url` 给规范链接、订阅源和站点地图提供绝对地址。检查订阅链接时，尤其要数一数仓库名出现了几次。产物里的 HTML 路径则可以剥掉挂载前缀，再去 `dist` 找对应的文件或目录首页。

## 校验通过再打包

构建作业先拿到 Pages 的部署信息，再用目标前缀跑检查，成功后将该次构建的 `dist` 上传为部署工件。发布作业等待构建完成，直接部署这份已检查的文件。这样出了问题，可以对着同一份工件复盘，不必猜测发布时是否又生成了另一批页面。

- 从归档点进一篇文章，检查封面和正文样式。
- 从搜索结果打开同一篇，比较跳转地址与页面的规范地址。
- 打开订阅源，确认每条文章链接的挂载前缀只出现一次。

我习惯在根路径和项目子路径各过一遍这套检查。将来站点迁回自定义域名时，只需要切换构建参数，文章里彼此引用的路由可以继续沿用。
