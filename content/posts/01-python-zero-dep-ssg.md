给星环手记添一篇文章，我只想写好正文，跑一次构建，在本地打开新页面。站点的深蓝底色和黑胶纹理可以慢慢打磨，发布过程越平常越好。用 Python 标准库搭建主流程，出了问题时，我可以沿着一份源稿，追到它在归档、正文和搜索索引里的三个去处。

## 先把内容读成数据

读取阶段统一处理日期、标签和草稿标记。草稿在这里筛掉，归档和订阅源就能共用同一份公开条目。日期相同时，再用短名排出先后。只换文件遍历顺序，上下篇仍然能排在原来的位置。同一个短名会落到同一个输出目录，所以我会在写文件前检查重名，让错误直接报出两份源稿的名字。

```python
published = sorted(
    (post for post in posts if not post.draft),
    key=lambda post: (post.date, post.slug),
    reverse=True,
)
```

## 让渲染各管一段

文章正文与右侧目录从同一次 Markdown 解析中生成，标题改字时，两处锚点会一起更新。模板接收已经准备好的数据，普通文字先做 HTML 转义，再填入标题和摘要的位置。代码高亮交给 Pygments，这是内容渲染里唯一的第三方依赖。围栏内的文本单独处理，示例里的字符和空格才能原样呈现。

- 用 `pathlib` 写入每篇文章的目录页，用 `shutil` 拷贝本地封面和字体。
- 用同一组已发布条目生成归档、搜索索引和订阅源，让标题与短名保持一致。

## 把检查放到产物上

撤下一篇文章后，我会重新构建干净的输出目录，再看看旧页面和搜索结果是否一起消失。封面路径写错时，浏览器有时只留下一小块空白，跑一遍内部链接检查更容易找出源头。站点挂在仓库子路径时，也要拿实际产物走一遍[文章归档](/articles/)，确认点进正文后，样式、封面和下一篇都能沿着同一个前缀找到。
